# 1. 新增一个音色克隆或缓存音色克隆: /v1/audio/client_voices

克隆音色并缓存音色cache（只是缓存pt文件内容

form请求参数:


- audio_sample / pt 二选一：audio_sample从音频文件克隆音色，pt则接受一个有效的现有pt（不需要再做克隆）
    格式参考 curl -F "audio_sample=@$HOME/tmp/voice_consent/audio_sample_recording.wav;type=audio/x-wav" 
- persist: boolean 决定生成的音色文件是否在本地存储pt文件（且同时存储sqlite信息）（可选，默认false）
- consent: string 音色名称
- description: string 
- voice_id: 唯一ID

返回值：
- 成功返回 pt 文件流（如果输入是pt文件，则不需要输出文件流）
- 失败返回 JSON

注意：
- 如果不需要在本地存储，更新voice_id 及生成的 pt 文件在本地内存中的缓存（pt文件map LRU缓存上限：20）
- 如果指定了需要在本地存储 且 voice_id 在本地已存在，则更新本地的音色信息（除非本地的voice信息状态已锁定，这种情况下不应该做任何克隆操作，返回本地的pt文件）

# 2. 修改 TTS 接口实现

http://127.0.0.1:3456/v1/audio/speech

支持以下请求（注意：voice_id可以是sqlite本地存储的音色，也可以是通过 /v1/audio/remote_voices 创建驻留在内存中的音色信息）

curl -X POST http://127.0.0.1:3456/v1/audio/speech \
  -H "Content-Type: application/json" \
  -o output.wav \
  -d '{
    "model": "mtts",
    "input": "你好世界",
    "voice": {"id": "voice_xxx"}, 
    "response_format": "wav"
  }'
